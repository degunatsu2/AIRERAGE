# InputRecordings

入力の記録（docs/06_prototype_plan.md T1-9b）を置くフォルダ。Sandbox_Wire で F5 を押すと記録が始まり、もう一度押すと記録を終えてここに保存される（`rec_日時.txt`）。F6 で最新の記録を再生する（再生中にもう一度押すと止まる）。

- 不具合を再現したいときは、F5 で記録を始めてから操作し、不具合が起きたら F5 で保存して、ファイルをコミットする（またはチャットに貼る）。
- 記録の始めと再生の始めに、Sandbox_Wire のダミーを出現位置に戻す（同じ条件で再生するため）。ダミーに攻撃を当てた記録は、ダミーのいない照合のテスト（RecordedReplayTests）では一致しない。PC 間の照合に使う記録では、ダミーに当てない。
- `archive/` には、シミュレーションや状態の形式を変える前に記録したもの（今の版では読めないか、一致しない）を残す。照合のテストは `archive/` を読まない。
  - `*_state1.txt`: 状態の形式の版 1（ロープの巻き付きを加える前）の記録。
  - `*_state2.txt`: 状態の形式の版 2（アクション状態を加える前。Phase 2 の終わり）の記録。`windows_user_20261013_150656_typeA_state2.txt` はユーザーの Windows で記録したもの（3211 ティック、ワイヤーの接続 29 回、ロープの巻き付きあり）で、クラウドの Linux でも同じ最後の状態になった（2026-10-13、T2-9）。`cloud_linux_*_state2.txt` はクラウドの Unity で作ったもので、Windows でも一致した。
  - `windows_user_20261013_typeA.txt`: ユーザーの Windows で記録したもの（3600 ティック、状態の形式の版 1）。T2-9 の評価（`RollbackEvaluationTests`）で、人の入力として入力の部分だけを使う。
- 今は照合用の記録を置いていない（Phase 3 で攻撃を加えて状態の形式が版 3 になったため）。戦闘がまとまった段階で、クラウドとユーザーの Windows の記録を作り直して、PC 間の照合をもう一度行う。
- シミュレーションのコードを変えると、古い記録は一致しなくなる。照合が終わった記録は消してよい。
