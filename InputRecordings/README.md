# InputRecordings

入力の記録（docs/06_prototype_plan.md T1-9b）を置くフォルダ。Sandbox_Wire で F5 を押すと記録が始まり、もう一度押すと記録を終えてここに保存される（`rec_日時.txt`）。F6 で最新の記録を再生する（再生中にもう一度押すと止まる）。

- 不具合を再現したいときは、F5 で記録を始めてから操作し、不具合が起きたら F5 で保存して、ファイルをコミットする（またはチャットに貼る）。
- `archive/` には、シミュレーションを変える前に記録したもの（今の版では一致しない）を残す。照合のテストは `archive/` を読まない。
  - `archive/cloud_linux_type*_state1.txt`: 状態の形式の版 1（ロープの巻き付きを加える前）の記録。今の版では形式が違うので読めない。
  - `archive/windows_user_20261013_typeA.txt`: ユーザーの Windows で記録したもの（3600 ティック）。記録した版（コミット 68fd8a9 の前後）では、クラウドの Linux でも最後の状態が一致した（2026-10-13）。その後、ロープが地形に遮られても解除しない変更（D-33）と、外れた位置を残す変更で一致しなくなった。
- `windows_user_20261013_150656_typeA.txt`: ユーザーの Windows で記録したもの（3211 ティック、ワイヤーの接続 29 回、ロープの巻き付きあり）。クラウドの Linux でも同じ最後の状態になった（2026-10-13、T2-9）。
- `cloud_linux_*.txt` は、クラウド（Linux）の Unity で作った記録（ロープの巻き付きは含まない）。Windows の Test Runner で `RecordedReplayTests` を選んで実行し、一致すれば、Linux と Windows で同じ結果になっている（PC 間の決定性。docs/04_network.md 3.5）。
- シミュレーションのコードを変えると、古い記録は一致しなくなる。照合が終わった記録は消してよい。
