# 06. 最初のプロトタイプの実装計画（ワイヤー移動）

> ステータス: ドラフト v0.1（2026-10-12）。数値はすべて【仮】です。

---

## 1. 目的と範囲

**目的**: 戦闘やオンライン機能を作る前に、ワイヤーの操作感を検証できる、最小限の遊べるプロトタイプを作る。

**最優先**: キャラクターがマップ上を移動し、ワイヤーを射出し、対象に接続し、引っ張られて移動し、解除できること。

| 範囲に含める | 範囲に含めない |
|---|---|
| 走行、ジャンプ、空中制御、地形との衝突 | 攻撃、ガード、ゲージ |
| ワイヤーの射出、照準、エイムアシスト、接続、牽引、解除、慣性、強制解除、クールダウン | コイン、スコア、試合進行 |
| タイプA／Bの実装とプレイ中の切り替え | オンライン機能（ただし妨げない設計にする） |
| 検証用のアリーナ（グレーボックス）とタイム計測コース | 見た目の作り込み（箱と線で表示する） |
| デバッグ表示、調整用データ、スロー再生 | キャラクターの差別化 |
| 自動テスト、手動プレイテストのチェックリスト | 演出、サウンド |

---

## 2. オンライン対応を妨げないための約束

Phase 1 はローカルのみですが、次の点を最初から守ります。

1. シミュレーションは固定ティック（60Hz）の純C#（`Degunatsu.Core`）で、UnityEngine に依存しない。
2. キャラクターの動きは入力コマンド（`PlayerInput`）だけで決まる。Input System を直接読むのは Runtime のアダプターだけ。
3. キャラクターとワイヤーの状態は、すべて構造体（`CharacterState` / `WireState`）にあり、コピーと比較ができる。
4. Rigidbody を使わず、衝突は `ICollisionQuery` を通して調べる。
5. 同じ入力列からは、同じ状態が得られる（決定性のテストで保証する）。
6. 複数のキャラクターを同じ `SimWorld` で動かせる（2体目は入力の記録を再生するダミーなどで確認する）。

## 3. 操作（プロトタイプ）

| 操作 | ゲームパッド | キーボード |
|---|---|---|
| 移動・照準 | 左スティック | WASD |
| ジャンプ | South（A／×） | Space |
| ワイヤー（押して射出、押している間は接続、離して解除） | 右トリガー（RT／R2） | J |
| タイプA／Bの切り替え（デバッグ） | Select／View | Tab |
| スロー再生の切り替え（デバッグ） | 十字キー下 | F1 |
| 1ティック送り（デバッグ、一時停止中） | 十字キー右 | F2 |
| 位置のリセット | Start／Menu | R |

- 照準は左スティックの方向（アナログ）。入力がないときは「向いている方向の斜め上45°」（D-08）。
- キーボードは8方向。マウス照準は入れない（P-6）。

## 4. 初期パラメータ（すべて【仮】）

### 4.1 移動（MovementTuning）

| 項目 | 値 |
|---|---|
| 走行の最高速 | 8 m/s |
| 地上加速 ／ 空中加速 | 80 m/s² ／ 30 m/s² |
| ジャンプの初速 | 12 m/s |
| 空中ジャンプの回数 | 1 |
| 重力 ／ 最大落下速度 | 30 m/s² ／ 20 m/s |
| 当たり判定の箱の幅 ／ 高さ | 0.8 m ／ 1.8 m |
| 空中で入力がないときの減速 | 2 m/s² |
| 先行入力 ／ コヨーテタイム | 6 ティック ／ 6 ティック |

### 4.2 ワイヤー共通（WireTuning）

| 項目 | 値 | 備考 |
|---|---|---|
| 最大長 | 12 m | |
| フックの弾速 | 60 m/s | 最大長まで約0.2秒 |
| 外れたときの回収時間 | 10 ティック | |
| 解除後のクールダウン | 20 ティック | |
| エイムアシストの角度 | ±12° | |
| 最小ロープ長 | 1.0 m | |
| 最大接続時間 | 180 ティック（3秒） | |
| 接続中の最高速 | 22 m/s | 両タイプ共通の上限 |
| 解除時の出口速度の上限 | 18 m/s | 両タイプ共通の上限 |
| ロープが地形に遮られたら解除 | する | ロープの巻き付きは作らない |

### 4.3 タイプA: 物理・慣性重視（InertialWireModel）

| 項目 | 値 | 意味 |
|---|---|---|
| 巻き取り速度 | 8 m/s | ロープが縮む速さ。縮むほど振りが速くなる |
| スティックによる振りの力 | 10 m/s² | ロープに垂直な方向へ加える力 |
| 減衰 | 0.0 | 0 ならエネルギーが保存される |
| 接続時の初期ロープ長 | 接続した瞬間の距離 | |

### 4.4 タイプB: 操作追従重視（ResponsiveWireModel）

| 項目 | 値 | 意味 |
|---|---|---|
| 牽引速度 | 16 m/s | アンカーへ向かう目標速度 |
| 牽引の加速度 | 120 m/s² | 約0.13秒で目標速度に達する |
| スティックによる進路の調整 | 6 m/s | 牽引方向に垂直な速度の上限 |
| 牽引中の重力倍率 | 0.2 | |
| 到着とみなす半径 | 1.0 m | 到着したらその場で静止し、ぶら下がる【仮】 |

タイプBの最高速はタイプAより低くし、代わりに確実さと速さで勝る、という差を初期の仮説とします。

各タスクは単独で検証できる単位です。番号順に進めますが、T1-5 と T1-6 は入れ替えられます。

### T1-0. Unity プロジェクトの作成（Phase 0 の残り）

- **内容**: Phase 0 の作業一式（[05](05_roadmap.md)）。
- **完了条件**: Phase 0 の完了条件をすべて満たす。

### T1-1. Core の骨組み

- **内容**: `PlayerInput`、`CharacterState`、`SimWorld.Step()`、`ICollisionQuery`、テスト用の衝突ワールド（平面上の矩形の集まり）。
- **完了条件**:
  - [ ] [自動] 空のワールドで N ティック進めてもエラーにならない
  - [ ] [自動] 同じ入力列を2回実行すると、状態が完全に一致する（決定性）

### T1-2. キネマティックな移動

- **内容**: 走行、ジャンプ、空中ジャンプ、重力、接地判定、壁と天井との衝突、連続判定によるすり抜け防止。
- **完了条件**:
  - [ ] [自動] 地面に着地し、接地状態になる
  - [ ] [自動] ジャンプの最高到達点が、パラメータから計算した値と一致する（許容誤差内）
  - [ ] [自動] 最高速で厚さ 0.2m の壁に突っ込んでもすり抜けない
  - [ ] [自動] 天井に頭をぶつけたら、上向きの速度が0になる

### T1-3. ワイヤーの共通制御（WireController）

- **内容**: フェーズ（Ready → Firing → Attached → Cooldown、Firing → Retracting）、照準とエイムアシスト、接続判定、強制解除、クールダウン、速度の上限、解除時の慣性。運動モデルは仮の空実装で始める。
- **完了条件**:
  - [ ] [自動] 射程内の接続可能な面に向けて射出すると、正しい位置で Attached になる
  - [ ] [自動] 射程内に対象がなければ Retracting を経て Cooldown になる
  - [ ] [自動] Cooldown 中は射出できない
  - [ ] [自動] エイムアシストが、角度内の最も近い接続可能点を選ぶ
  - [ ] [自動] ロープが地形に遮られたら解除される
  - [ ] [自動] 最大接続時間を超えたら解除される
  - [ ] [自動] 解除時の速度が出口速度の上限で制限される

### T1-4. タイプA（InertialWireModel）

- **完了条件**:
  - [ ] [自動] 接続中、アンカーとの距離がロープ長を超えない
  - [ ] [自動] 減衰0、巻き取りなしで振ると、振り子の周期が 2π√(L/g) と許容誤差内で一致する
  - [ ] [自動] 巻き取ると、ロープ長が最小値まで縮む

### T1-5. タイプB（ResponsiveWireModel）

- **完了条件**:
  - [ ] [自動] 静止状態から接続すると、想定したティック数以内にアンカーに到着する
  - [ ] [自動] 牽引中の速度が牽引速度を超えない

### T1-6. 両タイプ共通の契約テスト

- **内容**: NUnit のパラメータ化テストで、同じテストを両モデルに適用する。
- **完了条件**:
  - [ ] [自動] 接続中の速度が共通の最高速を超えない
  - [ ] [自動] 接続中に地形をすり抜けない
  - [ ] [自動] Attached フェーズの間は、キャンセル判定用の「牽引中」フラグが常に立つ（D-18 の推奨案）
  - [ ] [自動] 解除後の速度が、両タイプとも同じ規則で計算される

### T1-7. Unity との接続

- **内容**: `SimulationRunner`（ティックループと描画の補間）、`UnityCollisionQuery`、`InputSystemAdapter`、`CharacterView`（箱）、`WireView`（LineRenderer）、カメラ（Cinemachine 3 で追従）、ScriptableObject の定義と変換。
- **完了条件**:
  - [ ] [手動] シーンを再生すると、キャラクターをパッドとキーボードで操作できる
  - [ ] [手動] ワイヤーが線で表示され、接続点が見える
  - [ ] [手動] プレイ中に ScriptableObject の値を変えると、すぐに挙動が変わる
  - [ ] [手動] Console にエラーや警告が出ない
  - [ ] [手動] 壁際でぶら下がり、ロープが壁面とほぼ平行になっても、「地形に遮られた」と誤判定されて外れない（Unity の Raycast が面の縁に当たる可能性があるため。テスト用の矩形ワールドでは起きない）

### T1-8. 検証用アリーナ（Sandbox_Wire）

- **内容**: グレーボックスで、仕様のアリーナ要素を一通り置く。
  - 小さな足場（幅1〜2m）の連なり
  - 細長い壁（厚さ0.2〜0.5m、高さ8m）
  - 空中の障害物とアンカーポイント
  - 天井が低い通路（引っかかりの確認用）
  - スタートとゴールがあるタイム計測コース（タイプA／Bの比較用）を2〜3本
- **完了条件**:
  - [ ] [手動] すべての要素にワイヤーで到達でき、引っかかって動けなくなる場所がない
  - [ ] [手動] コースのタイムが自動で計測・表示される

### T1-9. デバッグと調整のための機能

- **内容**:
  - デバッグHUD（アクション状態、ワイヤーのフェーズ、速度、ロープ長、クールダウン、選択中のタイプ、入力の表示）
  - 軌跡の表示（直近の数秒）
  - スロー再生（1/2、1/4）と1ティック送り
  - タイプA／Bの切り替え
  - 入力の記録と再生（不具合の再現用。決定性があるので同じ動きが再現される）
  - 計測（コースタイム、最高速、解除時の速度）
- **完了条件**:
  - [ ] [手動] 上記の機能がすべて使える
  - [ ] [手動] 記録した入力を再生すると、同じ軌道になる

### T1-10. プレイテストと調整

- **内容**: [07](07_quality.md) の手動チェックリストを実施し、仮の値を調整する。タイプA／Bを同じコースで比較し、結果を記録する。
- **完了条件**:
  - [ ] [手動] チェックリストを一通り実施し、結果と調整内容を記録した
  - [ ] [手動] タイプA／Bのコースタイムと所感を記録した（D-11 の判断材料）
