# 06. 最初のプロトタイプの実装計画（ワイヤー移動）

> ステータス: ドラフト v0.1（2026-10-12）。数値はすべて【仮】です。

---

## 1. 目的と範囲

**目的**: 戦闘やオンライン機能を作る前に、ワイヤーの操作感を検証できる、最小限の遊べるプロトタイプを作る。

**最優先**: キャラクターがマップ上を移動し、ワイヤーを射出し、対象に接続し、引っ張られて移動し、解除できること。

| 範囲に含める | 範囲に含めない |
|---|---|
| 走行、ジャンプ、空中制御、地形との衝突 | 攻撃、ガード、ゲージ |
| ワイヤーの射出、照準、エイムアシスト、接続、牽引、解除、慣性、強制解除、クールダウン | コイン、スコア、試合進行 |
| タイプA／Bの実装とプレイ中の切り替え | オンライン機能（ただし妨げない設計にする） |
| 検証用のアリーナ（グレーボックス）とタイム計測コース | 見た目の作り込み（箱と線で表示する） |
| デバッグ表示、調整用データ、スロー再生 | キャラクターの差別化 |
| 自動テスト、手動プレイテストのチェックリスト | 演出、サウンド |

---

## 2. オンライン対応を妨げないための約束

Phase 1 はローカルのみですが、次の点を最初から守ります。

1. シミュレーションは固定ティック（60Hz）の純C#（`Degunatsu.Core`）で、UnityEngine に依存しない。
2. キャラクターの動きは入力コマンド（`PlayerInput`）だけで決まる。Input System を直接読むのは Runtime のアダプターだけ。
3. キャラクターとワイヤーの状態は、すべて構造体（`CharacterState` / `WireState`）にあり、コピーと比較ができる。
4. Rigidbody を使わず、衝突は `ICollisionQuery` を通して調べる。
5. 同じ入力列からは、同じ状態が得られる（決定性のテストで保証する）。
6. 複数のキャラクターを同じ `SimWorld` で動かせる（2体目は入力の記録を再生するダミーなどで確認する）。

## 3. 操作（プロトタイプ）

| 操作 | ゲームパッド | キーボード＋マウス |
|---|---|---|
| 移動 | 左スティック | WASD |
| 照準 | 右スティック（倒していないときは左スティック） | マウスポインターの方向 |
| ジャンプ | South（A／×） | Space |
| ワイヤー（押して射出、押している間は接続、離して解除） | 右トリガー（RT／R2） | 左クリック（J でも可。どちらもマウスポインターの方向） |
| カメラのズーム（近づく／離れる。距離 12〜40 m【仮】） | RB／R1 ／ LB／L1（押している間） | ホイールを上／下 |
| タイプA／Bの切り替え（デバッグ） | Select／View | Tab |
| スロー再生の切り替え（デバッグ。1 → 1/2 → 1/4 → 一時停止 → 1） | 十字キー下 | F1 |
| 1ティック送り（デバッグ、一時停止中） | 十字キー右 | F2 |
| 入力の記録を開始／終了して保存（デバッグ。最大5分） | 十字キー上 | F5 |
| 最新の記録を再生／再生を止める（デバッグ） | 十字キー左 | F6 |
| 位置のリセット | Start／Menu | R |

- 照準（D-08）: ゲームパッドは右スティックを倒している間はその方向、倒していなければ左スティックの方向（アナログ）。どちらも入力がないときは「向いている方向の斜め上45°」。右スティックで照準すると、移動の向きに関係なくどの方向にも撃てる（ユーザーの提案、2026-10-12）。キーボード＋マウスはマウスポインターの方向（ユーザーの指示、2026-10-12）。最後に使った機器で切り替える。
- 照準のインジケーター: 照準の方向に半透明の線を出し、射出したときの結果を色で示す（緑 = 接続できる、赤 = 接続できない地形に当たる、灰 = 届かない）。射程の限界は円で示す（色は仮にワイヤーと同じ紫。後でキャラクターとワイヤーの輪郭線と一緒にプレイヤーカラーに合わせる）。
- ズームのボタン: ユーザーの案は R2／L2 だったが、R2（右トリガー）はワイヤーに使っているため、RB／LB にした。

### 4.3 タイプA: 物理・慣性重視（InertialWireModel）

| 項目 | 値 | 意味 |
|---|---|---|
| 巻き取り速度 | 8 m/s | ロープが縮む速さ。縮むほど振りが速くなる |
| スティックによる振りの力 | 10 m/s² | ロープに垂直な方向へ加える力 |
| 減衰 | 0.0 | 0 ならエネルギーが保存される |
| 接続時の初期ロープ長 | 接続した瞬間の距離 | |
| 接続直後の速さの下限 | 14 m/s | 接続した瞬間の速さがこれより遅いときだけ、接続点の方向へ強く引いてこの速さを保つ（止まった状態からの初速の遅さを補う。ユーザーの指示、2026-10-12）。振りが速くなれば通常の巻き取りに戻る |
| 下限を保つ時間 ／ 巻き取りの速さまで下げる時間 | 20 ティック ／ 20 ティック | 合わせて約0.67秒。引きの間はロープがたるまない |

### 4.4 タイプB: 操作追従重視（ResponsiveWireModel）

| 項目 | 値 | 意味 |
|---|---|---|
| 牽引速度 | 16 m/s | アンカーへ向かう目標速度 |
| 牽引の加速度 | 120 m/s² | 約0.13秒で目標速度に達する |
| スティックによる進路の調整 | 6 m/s | 牽引方向に垂直な速度の上限 |
| スティックによる速さの調整【試行】 | 4.2 の「入力の影響」 | 接続点の方向に入れると速く、逆向きで遅く（例: 左上の接続点なら、左・上で速く、右・下で遅く） |
| 牽引中の重力倍率 | 0.2 | |
| 到着とみなす半径 | 1.0 m | 到着したらその場で静止し、ぶら下がる【仮】 |

タイプBの最高速はタイプAより低くし、代わりに確実さと速さで勝る、という差を初期の仮説とします。

### T1-2. キネマティックな移動

- **内容**: 走行、ジャンプ、空中ジャンプ、重力、接地判定、壁と天井との衝突、連続判定によるすり抜け防止。

  - [ ] [自動] エイムアシストが、角度内の最も近い接続可能点を選ぶ
  - [x] [自動] ロープが地形に遮られたら解除される（`ReleaseWhenLineBlocked` を有効にしたとき。既定は解除しない。D-33）
  - [ ] [自動] 最大接続時間を超えたら解除される
  - [ ] [自動] 解除時の速度が出口速度の上限で制限される

  - 計測（コースタイム、最高速、解除時の速度）
- **入力の記録と再生（T1-9b）の仕様**:
  - F5（十字キー上）で記録を始め、もう一度押すと記録を終えて、プロジェクト直下の `InputRecordings/` にテキストで保存する（開始時の状態、入力、最後の状態のチェックサム、記録したときの調整値）。不具合の報告に添付できる。1回の記録は【仮】最大5分で、超えたら自動で終えて保存する。
  - 記録中に位置のリセット（R）やタイプの切り替え（Tab）をすると、そこで記録を終えて保存する（入力以外で状態や動きが変わるため）。
  - F6（十字キー左）で、`InputRecordings/` の最新の記録を再生する（記録中なら、記録を終えて保存してから再生する）。記録したときのタイプに切り替え、記録を始めたときの状態に戻してから、記録した長さだけ記録した入力で進める。再生中のプレイヤーの入力は無視し、照準のインジケーターも再生中の入力で表示する。再生中にもう一度 F6 を押すと止まる（R でも中止できる）。再生中は記録しない。
  - 再生の最後に状態のチェックサムを記録と比べ、`Replay OK` か `Replay MISMATCH` を左下に出す。調整値が記録したときと違うと、Console に警告を出す。
  - 別の PC で記録したファイルは、テスト `RecordedReplayTests`（明示的に選んだときだけ実行）で照合できる。PC 間の決定性の確認に使う（[04](04_network.md) 3.5、R-11）。シミュレーションのコードを変えると、古い記録は一致しなくなる。
- **完了条件**:
  - [ ] [手動] 上記の機能がすべて使える
  - [ ] [手動] 記録した入力を再生すると、同じ軌道になる
