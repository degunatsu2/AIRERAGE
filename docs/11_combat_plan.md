# 11. 戦闘基盤の実装計画（Phase 3）

> ステータス: ドラフト v0.1（2026-10-13）。数値はすべて【仮】です。仕様は [01](01_game_design.md) の 6章、完了条件は [05](05_roadmap.md) の Phase 3、判断事項は [02](02_open_decisions.md) の B-4。

## 1. 目的と範囲

**目的**: 攻撃、キャンセル、ガード、ジャストガード、被弾、コンボを、データで調整できる形で作る。ロールバック（Phase 2）の上で、オンラインでも命中が全員の画面で一致することまで確かめる。

| 範囲に含める | 範囲に含めない |
|---|---|
| 攻撃の状態とフレームデータ（発生・持続・硬直）、攻撃の種類（地上／空中 × ニュートラル／横／上／下） | 特殊アクション、必殺技、方向転換（Phase 5） |
| 命中の判定、ダメージ、HP、ヒットストップ、のけぞり、吹き飛び | コイン、撃破後の復帰、試合の進行（Phase 4） |
| キャンセル規則（攻撃→攻撃、攻撃→ワイヤー、ワイヤー→攻撃）とワイヤーキャンセルのクールタイム（P-1） | キャラクターごとの差（Phase 5） |
| ガード、ジャストガード | アニメーション（今は箱の色と線で示す） |
| ゲージの獲得 | |
| 検証用のダミー（ローカルで攻撃を当てる相手） | |

## 2. 構成の方針

- 戦闘のロジックは Core の `Degunatsu.Core.Combat`（純C#、決定的）。状態は `CharacterState.Action`（`ActionState`）に値で持つので、巻き戻しと PC 間のチェックサムにそのまま乗る。
- 状態の遷移は `ActionController` の1か所で決める（[01](01_game_design.md) 6.3 の実装原則）。アニメーションや表示から状態を変えない。
- 攻撃のデータは Core の `[Serializable]` な設定クラス（`CombatTuning` / `AttackData`）に置き、`CharacterConfig.Combat` として ScriptableObject（`DefaultCharacter.asset`）で調整する。仮値は初期値の1か所にだけ書く。
- 命中の判定はキャラクターどうしの関係なので、`SimWorld` が全員のティックを進めた後に、決まった順番（プレイヤーの番号の順）で解決する（T3-2）。

### 3.1 T3-1 の仕様（今の動き）

| 項目 | 内容 |
|---|---|
| ボタン（【仮】。D-35） | 攻撃: マウスの右ボタン ／ キーボードの K ／ ゲームパッドの X（左の面のボタン）。ワイヤー（左ボタン ／ J ／ RT）、ジャンプ（Space ／ A）は今までどおり |
| 攻撃の種類 | 押したときに地上か空中かと、移動の入力（WASD ／ 左スティック）の向きで決まる。上か下に入れていれば上・下の攻撃、横なら横の攻撃（その向きを向く）、入れていなければニュートラル。斜めは上下を優先【仮】 |
| 始められるとき | Free のとき。ワイヤーを射出中・接続中は始められない（ワイヤー→攻撃のキャンセルは T3-3） |
| 攻撃中 | 移動・ジャンプ・ワイヤーの入力を無視し、向きも変えない。地上では止まり、空中では勢いのまま落ちる。押し続けても次の攻撃は出ない（もう一度押す）。硬直が終わったティックから次の行動ができる |
| 表示（仮） | 発生 = 黄、持続 = 赤、硬直 = 青。デバッグ表示（右上）に「Action Attack GroundSide Active (9/28t)」のように出る |

## 5. 確認方法

- ロジックは Core のテスト（dotnet と Unity の EditMode）で確かめる。攻撃を含む入力で、巻き戻しても全員が同じ状態になることも確かめる。
- 状態の形式を変えたので（版 3）、それより前の入力の記録は `InputRecordings/archive/` に移した。戦闘がまとまった段階で、記録を作り直して PC 間で照合する（T3-8）。

### 5.1 T3-1 の確認の手順

1. Sandbox_Wire を再生する。
2. 地上で、何も入れずに攻撃（右クリック ／ K ／ X）→ キャラが 黄 → 赤 → 青 → 元の色 と変わる。右上の「Action」の行に、攻撃の種類と段階が出る。
3. 上・下・横（WASD ／ 左スティック）を入れながら攻撃 → 「GroundUp」「GroundDown」「GroundSide」になる。横は入れた向きを向く。
4. 走りながら攻撃 → その場で止まる。ジャンプ中に攻撃 → 「Air…」になり、勢いのまま落ちる。
5. 攻撃中にジャンプやワイヤーを押しても出ない。ワイヤーでぶら下がっている間は攻撃できない（T3-3 で、接続中の攻撃でワイヤーを解除する形などを加える）。
6. 確認すること: ボタンの位置が押しやすいか／攻撃の長さ（全体で 0.3〜0.5 秒）の感覚／斜めのときに上下が優先されるのが自然か。
