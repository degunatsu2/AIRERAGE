## 2. 構成の方針

- 戦闘のロジックは Core の `Degunatsu.Core.Combat`（純C#、決定的）。状態は `CharacterState.Action`（`ActionState`）などに値で持つので、巻き戻しと PC 間のチェックサムにそのまま乗る。
- 状態の遷移は `ActionController` の1か所で決める（[01](01_game_design.md) 6.3 の実装原則）。アニメーションや表示から状態を変えない。
- 攻撃のデータは Core の `[Serializable]` な設定クラス（`CombatTuning` / `AttackData`）に置き、`CharacterConfig.Combat` として ScriptableObject（`DefaultCharacter.asset`）で調整する。仮値は初期値の1か所にだけ書く。
- 命中の判定はキャラクターどうしの関係なので、`SimWorld` が全員のティックを進めた後に解決する。同じティックの相打ちが順番で変わらないよう、先に全員分の命中を集めてから、プレイヤーの番号の順に当てる（T3-2）。
- 1つの攻撃は、判定（`AttackHit`、1〜4つ）と動き（`AttackMotion`、攻撃中に速度を決める区間）の並びで表す。二段技や飛び込みも、データの組み合わせで作る（キャラクターごとの固有ロジックを増やさない）。

### 3.15 友達との対戦の指摘への対応（2026-10-13）

| 指摘 | 対応 |
|---|---|
| 加速リングを逆側からも反応させてほしい | 両方向に効くようにした: 通っている向き（リングの向きか、その逆）に加速する。リングの向きに対して真横に入ったときだけ効かない。見た目は、中心から両方向へ流れる「< >」。これで、上から中央のリングに落ちると下向きに加速し（中央のジャンプ台に戻る）、左右のリングを外向きに吹き飛ばされると外向きに加速する（撃破されやすくなる） |
| ワイヤーで動きながらの攻撃が当てにくく、戦闘が起きにくい | 全部の攻撃の判定の箱を、縦横とも約 2.5 倍にした（体の近くも含むように、キャラクターの側の端はおおむね残して、攻撃の向きへ広げた。値は 4 章の表）。地上技は、相手との距離 0〜6m で 2 段とも当たる（前は 0.4〜2.6m。踏み込みの距離に判定の大きさが加わるため） |

### 3.16 ワイヤーの挙動の調整し直し（D-50。2026-10-14、ユーザーの要望。タイプA）

プレイテストで挙動が不評だったため、上下の入力の割り当てを変えた（3.4 の D-41 の表は、この変更の前の動き）。

| 入力（接続中） | ロープの長さ | 振り |
|---|---|---|
| 何も押さない（縦の入力が -0.5〜0.9） | **保つ**（張力を保ったまま。D-41 で下を押したときの動き） | 左右の入力だけで、強めに振る（16 m/s²）。接続直後に遅ければ、振りの方向の速さを下限（16 m/s）まで上げる |
| 上（真上に近い入力だけ。0.9 以上） | 巻き取る（8 m/s。D-41 の前の標準の動き） | ロープに垂直な方向の力（10 m/s²）。接続直後に遅ければ、接続点の方向へ強く引く |
| 下（斜め下を含む。-0.5 以下） | **伸ばす**（6 m/s【仮】。最大長 12m まで） | 左右の入力だけで、強めに振る（16 m/s²） |

- **初速**: 接続直後の速さの下限を 14 → 16 m/s【仮】にした（`StartPullSpeed`）。
- **逆向きに刺したときの慣性**: 接続した瞬間に、接続点から遠ざかる向きに動いていたら、その向きの速さを接続点へ向かう向きに反転させる（速さは保つ。ロープに垂直な向きの速さはそのまま）。以前は、遠ざかる向きの速さはロープが張った瞬間に止められて失われていた。`WireTuning.AttachReverseOutward`（1 で全部反転、0 で以前の動き。0〜1）。ワイヤーの共通制御（`WireController`）なのでタイプB にも効く（凍結中。D-11）。
- 割り当ては調整値: `InertialWireTuning` の `NeutralMode` / `UpMode` / `DownMode`（`WireLengthMode`: Reel / Hold / ReelOut）、`ReelSpeed`、`ReelOutSpeed`、`UpInputThreshold`、`DownInputThreshold`、`HoldSwingAcceleration`。どれも【仮】。D-41 の `FastReelSpeed`（上で素早く縮む）はなくした（上はふつうの巻き取りになったため）。
- 確認の手順は 5.14。

## 5. 確認方法

- ロジックは Core のテスト（dotnet と Unity の EditMode）で確かめる。攻撃を含む入力で、巻き戻しても全員が同じ状態になることも確かめる。
- 状態の形式を変えたので（版 3。今は版 15）、それより前の入力の記録は `InputRecordings/archive/` に移した。戦闘がまとまった段階で、記録を作り直して PC 間で照合する（T3-9）。

### 5.1 T3-1 の確認の手順

1. Sandbox_Wire を再生する。
2. 地上で攻撃（右クリック ／ K ／ X）→ キャラが 黄 → 赤（前へ踏み込む）→ 青（上へ飛び出す）→ 元の色 と変わる。右上の「Action」の行に、攻撃の種類（Ground）と段階が出る。左右どちらを入れても「Ground」で、入れた向きへ進む。
3. ジャンプ中に攻撃 → 何も入れなければ「AirNeutral」、上・下・横を入れると「AirUp」「AirDown」「AirSide」。勢いのまま落ちる。
4. 地上技の後に、空中ジャンプやワイヤーですぐ動けるか（「素早く空中を動くために一度地上に降りる」使い方ができるか）。
5. 確認すること: 地上技の踏み込みと飛び出しの距離・高さ／ボタンの押しやすさ／斜めのときに上下が優先されるのが自然か。

### 5.2 T3-2 の確認の手順

1. Sandbox_Wire を再生する。出現位置の右に灰色のダミーが立っている。
2. ダミーに向かって地上技を出す → 赤い枠（攻撃の判定）がダミーに重なると、両方が一瞬止まり（ダミーは白）、ダミーがピンクになって右上へ飛ぶ。右上の「Dummy」の行に、のけぞりの残りとコンボが出る。
3. 空中の攻撃も当ててみる: 上（打ち上げ）、下（たたき落とし）、横（横へ飛ばす）、ニュートラル（体の周り）。ダミーがのけぞっている間に次の攻撃を当てると、コンボの数が増える。
4. R でダミーと自分を出現位置に戻す。
5. 確認すること: 当たった手応え（ヒットストップの長さ）／吹き飛びの向きと強さ／判定の大きさと位置が見た目と合っているか／空中でつなげられそうか（コンボの手応え）。ダメージやコインはまだ出ない（Phase 4）。

### 5.3 T3-2b の確認の手順

1. Sandbox_Wire を再生する。
2. ダミーに向かって地上技 → 前へ踏み込みながら1段目、斜め上へ飛び出しながら2段目が当たる（右上の「Dummy」の行のコンボが 2 になる）。赤い枠が、2段目では斜め上に移る。前の版より少し遠くまで進む。
3. ジャンプ中に下を入れて攻撃（撃破技）→ 金色のチャージの間は勢いのまま動き、その後、斜め下へ飛び込む。ダミーに当てると斜め下へ飛ぶ。
4. 撃破技の倍率を比べる: (a) その場でジャンプして打つ、(b) ワイヤーで速く振っている途中に解除して、すぐ打つ。(b) のほうがダミーが速く遠くへ飛ぶ。
5. ワイヤーで接続中に、(a) 下を押し続ける → ロープの長さが変わらないまま左右で振れる、(b) 上を押し続ける → ロープが素早く縮む、(c) 何も押さない → 今までどおり。
6. 確認すること: 地上技の距離と2段目の判定の位置／撃破技のチャージの長さ（16 ティック）と飛び込みの角度／倍率の効き方（止まって打つと弱く、速いと強い）／ワイヤーの上下入力の操作感（上下とみなす入力の大きさ、上の巻き取りの速さ）。

### 5.4 T3-3 の確認の手順

1. `Assets/_Project/Scenes/Sandbox_Combat.unity` を開いて再生する（新しいシーン）。中央の足場に自分、右端の近くと左右の足場に灰色のダミーが3人いる。遠くに赤い枠（ステージの範囲）がある（ホイールでズームアウトすると見える）。
2. 足場から歩いて落ちる → 赤い枠の下を越えると、出現位置に戻る。右上のデバッグ表示の「Action」の行の「Fall」が 1 増える（「KO」は増えない）。
3. 右端の近くのダミーに地上技を当てて、足場の外へ飛ばす → ダミーが落ちて出現位置に戻り、ダミーの行の「Fall」と、自分の「KO」が 1 増える。

### 5.14 ワイヤーの挙動の調整し直しの確認の手順（3.16。D-50）
