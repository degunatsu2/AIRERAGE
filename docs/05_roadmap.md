# 05. 開発フェーズと完了条件

> ステータス: ドラフト v0.1（2026-10-12）
> 各フェーズの中は、小さなタスクに分けて「目的と完了条件の整理 → 既存コードの確認 → 方針の説明 → 最小限の変更 → テスト → できなかった検証の明記 → 報告」のサイクルで進めます。
> 完了条件のうち **[自動]** は自動テスト、**[手動]** は Unity Editor 上の操作か手動プレイテストで確認する項目です。

---

## 全体の流れ

```
Phase 0  環境構築・合意
   ↓
Phase 1  ワイヤー移動プロトタイプ（ローカル）     ← 最初の実装の対象
   ↓
Phase 2  オンライン技術検証（移動＋ワイヤーの同期） ← 判断ゲート: 同期方式（案A／案B）
   ↓
Phase 3  戦闘基盤（ローカル → オンライン）         ← 判断ゲート: 空中コンボの遅延耐性
   ↓
Phase 4  試合ルール・コイン経済・目標地点
   ↓
Phase 5  キャラクターの差別化・ゲージ技
   ↓
Phase 6  アリーナ・ギミック・UI・セッション
   ↓
Phase 7  バランス調整・プレイテスト・配布
```

操作感の調整（Phase 1 の内容）は、Phase 2 以降も並行して続けます。ネットワーク対応はローカル版の完成を待たずに、Phase 2 で早めに検証します。

## Phase 2: オンライン技術検証（移動＋ワイヤーの同期）

**目的**: ロールバック方式（D-14）で、移動とワイヤーの同期が操作感を損なわないか、PC 間で決定性が保たれるかを確かめる。

**範囲**: [04 の6章](04_network.md)。

**完了条件**:
- [ ] 4人が接続し、全員が移動とワイヤーを使える（Multiplayer Play Mode またはビルド） [手動]
- [ ] 往復遅延 100ms でも、自キャラの移動とワイヤーの反応に遅れを感じず、相手の巻き戻し（ワープ）が目立たない [手動]
- [ ] ワイヤーの接続先と全員の位置が、全員の画面で一致する（チェックサムが一致し続ける） [手動＋自動]
- [ ] 入力の交換・予測・巻き戻し・時刻の同期が、Core 内の疑似ネットワーク（遅延・欠落の模擬）でテストされている [自動]
- [ ] パケットロス 2% でも状態が破綻しない [手動＋自動]
- [ ] 別の PC どうしで、同じ入力から同じ状態になる（決定性。R-11） [手動＋自動]
- [ ] 入力遅延と巻き戻しの上限の値を決め、結果を 02 に記録する

## Phase 3: 戦闘基盤

**目的**: 攻撃、キャンセル、ガード、ジャストガード、被弾、コンボを、データ駆動で作る。オンラインでの命中確定まで含める。

**前提となる判断**: D-17〜D-23

**完了条件**:
- [ ] 攻撃のフレームデータ（発生、持続、硬直、キャンセル窓）を ScriptableObject で調整できる [手動]
- [ ] キャンセル規則（攻撃→攻撃は1チェーン1回、攻撃→ワイヤー、牽引中のみワイヤー→攻撃）がテストで保証されている [自動]
- [ ] ガード、ジャストガードの受付時間とクールタイムがテストで保証されている [自動]
- [ ] 攻撃のワイヤーキャンセルのクールタイムが働き、クールタイム中は攻撃をワイヤーでキャンセルできないことをテストで確認している [自動]
- [ ] ワイヤーキャンセル時のエフェクトと、キャラ周囲の半透明の円形クールタイマーが表示される [手動]
- [ ] ゲージの獲得・消費が正しい [自動]
- [ ] オンラインで、命中・ガード結果が全員の画面で一致する（確定ティックで一致） [手動]
- [ ] **判断ゲート**: 往復遅延 100ms で空中コンボの基本ルートが成立する（[04 の2.1](04_network.md) の基準） [手動]
