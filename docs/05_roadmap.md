# 05. 開発フェーズと完了条件

> ステータス: ドラフト v0.1（2026-10-12）
> 各フェーズの中は、小さなタスクに分けて「目的と完了条件の整理 → 既存コードの確認 → 方針の説明 → 最小限の変更 → テスト → できなかった検証の明記 → 報告」のサイクルで進めます。
> 完了条件のうち **[自動]** は自動テスト、**[手動]** は Unity Editor 上の操作か手動プレイテストで確認する項目です。

---

## 全体の流れ

```
Phase 0  環境構築・合意
   ↓
Phase 1  ワイヤー移動プロトタイプ（ローカル）     ← 最初の実装の対象
   ↓
Phase 2  オンライン技術検証（移動＋ワイヤーの同期） ← 判断ゲート: 同期方式（案A／案B）
   ↓
Phase 3  戦闘基盤（ローカル → オンライン）         ← 判断ゲート: 空中コンボの遅延耐性
   ↓
Phase 4  試合ルール・コイン経済・目標地点
   ↓
Phase 5  キャラクターの基盤（特殊攻撃 2 つ・必殺技・キャラクターのデータ。仮キャラクター 2 体）
   ↓
Phase 6  ゲームの流れ（タイトル → メニュー → キャラクター選択 → ステージ選択 → 対戦）・ステージの仕組み・セッション
   ↓
Phase 7  コンテンツ（キャラクター 8 体、ステージ 20 個、CPU）
   ↓
Phase 8  バランス調整・プレイテスト・配布
```

Phase 5 以降は、ユーザーの方針（2026-10-15。D-52〜D-54: キャラクター 8 体・ステージ 20 個、特殊攻撃 2 つ（Q・E）と必殺技（R）、一般的なゲームの流れ）に合わせて組み直した。

操作感の調整（Phase 1 の内容）は、Phase 2 以降も並行して続けます。ネットワーク対応はローカル版の完成を待たずに、Phase 2 で早めに検証します。

## Phase 2: オンライン技術検証（移動＋ワイヤーの同期）

**目的**: ロールバック方式（D-14）で、移動とワイヤーの同期が操作感を損なわないか、PC 間で決定性が保たれるかを確かめる。

**範囲**: [04 の6章](04_network.md)。

**完了条件**:
- [x] 4人が接続し、全員が移動とワイヤーを使える（Multiplayer Play Mode またはビルド） [手動] — 2026-10-13、Multiplayer Play Mode の4人でユーザーが確認（同じ PC の中）
- [x] 往復遅延 100ms でも、自キャラの移動とワイヤーの反応に遅れを感じず、相手の巻き戻し（ワープ）が目立たない [手動] — 2026-10-13、Multiplayer Play Mode で遅延を模擬してユーザーが確認
- [x] ワイヤーの接続先と全員の位置が、全員の画面で一致する（チェックサムが一致し続ける） [手動＋自動] — 同じ PC の中の通信の自動テスト、Multiplayer Play Mode と友人の PC との LAN でユーザーが確認（2026-10-13）
- [x] 入力の交換・予測・巻き戻し・時刻の同期が、Core 内の疑似ネットワーク（遅延・欠落の模擬）でテストされている [自動] — T2-3〜T2-6
- [x] パケットロス 2% でも状態が破綻しない [手動＋自動] — 疑似ネットワーク（欠落 20% まで）、同じ PC の中の通信（欠落 5%）の自動テストと、ユーザーの確認（欠落 5% でも Desyncs 0）
- [x] 別の PC どうしで、同じ入力から同じ状態になる（決定性。R-11） [手動＋自動] — Windows と Linux で互いの記録が一致（2026-10-13）
- [x] 入力遅延と巻き戻しの上限の値を決め、結果を 02 に記録する — D-34（2026-10-13）

## Phase 3: 戦闘基盤

**目的**: 攻撃、キャンセル、ガード、ジャストガード、被弾、コンボを、データ駆動で作る。オンラインでの命中確定まで含める。詳細は [11_combat_plan.md](11_combat_plan.md)。

**前提となる判断**: D-17〜D-23

**完了条件**:
- [ ] 攻撃のフレームデータ（発生、持続、硬直、キャンセル窓）を ScriptableObject で調整できる [手動]
- [x] キャンセル規則（攻撃→攻撃は1チェーン1回、攻撃→ワイヤー、牽引中のみワイヤー→攻撃）がテストで保証されている [自動]（`CancelTests`。[11](11_combat_plan.md) T3-4）
- [x] ガード、ジャストガードの受付時間とクールタイムがテストで保証されている [自動]（`GuardTests`。[11](11_combat_plan.md) T3-5）
- [x] 攻撃のワイヤーキャンセルのクールタイムが働き、クールタイム中は攻撃をワイヤーでキャンセルできないことをテストで確認している [自動]（`CancelTests`）
- [x] ワイヤーキャンセル時のエフェクトと、キャラ周囲の半透明の円形クールタイマーが表示される [手動]（2026-10-13、ユーザーの確認。[11](11_combat_plan.md) 3.8、T3-7）
- [ ] ゲージの獲得・消費が正しい [自動]（獲得はテスト済み（`GaugeTests`）。消費は Phase 5 のゲージ技と合わせる）
- [x] オンラインで、命中・ガード結果が全員の画面で一致する（確定ティックで一致） [手動]（2026-10-13、ユーザーが友達と対戦して、ネットワークの問題はなかった。[11](11_combat_plan.md) T3-8）
- [ ] **判断ゲート**: 往復遅延 100ms で空中コンボの基本ルートが成立する（[04 の2.1](04_network.md) の基準） [手動]（友達との対戦で、ワイヤーで動きながらの攻撃が当てにくいという指摘があり、判定とヒットストップを大きくした。もう一度の確認待ち。[11](11_combat_plan.md) 3.15、5.13）
